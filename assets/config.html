留空就是用各平台的官方地址；但用中转站 / 自建网关时不能留空 —— 那等于拿网关发的 Key 去敲官网，必然 401，必须把地址改成你自己的网关地址。
自定义接口没有内置协议，得靠这块说明「请求怎么发、结果从哪儿取」。
最小可用示例（同步接口，提交后响应里直接带产物地址）： 
{
  "auth": {"type": "bearer"},
  "result_path": "data.images",
  "result_url_field": "url"
}
响应里只有一个地址时可以连 result_path 都不写，程序会自己找。 异步接口（先拿 task_id 再轮询）再加： 
{
  "submit": {"task_id_path": "data.task_id"},
  "poll": {"url": "https://…/{{task_id}}", "status_path": "data.status",
           "result_path": "data.result"}
}
字段含义见 references/providers.md 的 generic_http 一节。

添加模型

这里填的是厂商那边的模型名，必须严格照抄厂商的命名规则 —— 大小写、版本号、日期后缀都不能改，写错接口会直接报「模型不存在」。
以厂商控制台里显示的模型名为准，手动填写。
只影响这个页面和列表里的显示。没有改名需求就留空， 默认直接用上面的模型名称。
输入模态 —— 这个模型能接受什么
输出模态 —— 这个模型能产出什么
功能标签：告诉 AI 助手这个模型吃什么、吐什么，它才好挑对模型。 输入里勾上「图片」，就会同时标成支持图生图 / 图生视频。
这里设的是这个模型每次生成的默认尺寸。发请求时也可以在提示里临时指定，临时的优先。 选「不指定」时用的是平台默认值 —— 不少平台会直接给 2048×2048（单张 5MB 以上）， 网页、PPT、聊天窗这类下游往往用不到这么大，建议选 1328×1328 或 1024×1024。 注意：不是每个模型都支持所有尺寸（比如有的只收 1024×1024，有的用「1K/2K/4K」这种叫法）， 以厂商文档为准；填了不支持的值平台会报错。
清晰度和时长直接影响花费：1080p / 10 秒比 480p / 5 秒贵得多。 不是每个模型都支持全部组合（可灵一般 5/10 秒，即梦 3~12 秒），以厂商文档为准。
音色名以厂商控制台为准（各家叫法不同：Cherry、alloy、BV001…），留空就用平台默认音色。 语速通常 0.5~2.0，超出范围平台会报错。
拖动滑块或直接填数字都行。越大越容易被选中；同一优先级内按权重比例分流，例如 50 和 30 大约是 62% 与 38%。
没有优先级需求就保持 1（默认值）。 数字越小越优先：优先级 1 的模型永远压过 2，只有前面的都不可用时才会轮到后面的。
优先级负责「分档」，权重负责「同档内分流」。想让几个模型按权重分摊流量 → 都填 1； 想设成「主用 + 备用」→ 备用模型填 2，主用挂了才会自动切过去。
